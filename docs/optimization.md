# 从栈式 MIPS 到数据流与函数调用优化

贾鑫洋　24373313

本文记录 2026 竞速排序作业的优化实现、正确性约束和本地验证结果。实现基于已有编译器，参考 Acc 将优化步骤组织为独立模块的方式，并适配本工程的 IR、字符类型和 MIPS 调用机制。在首轮平台反馈后，进一步参考 Salyut-J 的优化流水线、内联、只读全局量消除和循环优化，补强跨函数计算的简化。

## 一、从访存成本确定优化方向

原有后端为表达式结果分配栈槽。一次加法通常需要先加载两个操作数，再计算并把结果写回栈。循环中还会反复加载局部变量，递归函数会重复执行这些指令。

课程以动态执行的 FinalCycle 评分，除法、乘法、跳转或分支、访存、其他指令的权重分别为 18、3、1.5、2、1。因此，这次优先降低访存次数和常量除法的成本，同时通过 IR 优化消除计算本身。

优化入口位于 `optimize/OptimizeManager.java`，按以下次序执行。

1. 从 main 出发搜索调用图，删除不可达函数。
2. 简化常量分支，删除终结指令后的内容和不可达基本块。
3. 传播局部标量的已知存储值，合并块内重复加载。
4. 折叠常量、化简代数恒等式，依据支配关系合并公共子表达式。
5. 根据活跃分析删除无用存储，再沿值依赖关系删除死指令。
6. 传播只读全局标量，内联小函数，求值常量参数的纯函数调用，再次清理死代码。
7. 重复三轮模块优化，然后外提安全的循环不变计算，缓存循环中参数不变的纯函数调用。
8. 再次清理 IR，在目标代码生成阶段执行寄存器分配、常量运算优化和满足条件的递归记忆化。

IR 简化最多执行八轮。常量折叠可能让分支变为固定跳转，分支删除又可能暴露无用指令，因此每轮结束后比较函数文本，已经稳定的函数提前退出。

## 二、传播值时必须同时考虑控制流和内存

局部标量在本工程中通过 alloca、load、store 表示。优化器扫描所有使用位置，只把地址用于直接加载和存储的局部标量纳入可传播集合。数组和地址已经传出的对象保留内存访问语义。

每个基本块维护出口处已知的“存储位置到值”映射。块入口取全部前驱出口映射的交集，只有所有路径提供同一值时才继续传播。遇到 store 更新对应位置。反复求解到映射稳定后，再统一替换 load 的使用者。

例如，两个分支都给 x 写入 7，汇合后读取 x 可以得到常量 7。如果某个分支写入 8，交集会丢弃 x 的已知值。循环回边也参与求解，避免把第一轮循环的值当成以后每轮的值。

对一般内存，只合并同一基本块内、同一指针上的重复加载。任何存储或调用都会清空这部分缓存。数组参数可能指向同一数组，例如 `set(a, a)` 中第二个参数的写入会影响第一个参数的读取。清空缓存可以保留这种别名关系。

## 三、公共子表达式消除与循环外提

`ControlFlow` 根据块末尾的跳转建立前驱和后继关系，再迭代计算支配集合。

表达式键包含操作类型、结果类型、操作数类型及名称。加法、乘法以及相等性比较会规范化操作数顺序。合并表达式时要求已有定义所在块支配当前块，以保证复用的值在所有到达路径上都已经计算。减法和除法保留操作数顺序。

GVN 处理算术、比较、类型转换和地址计算。加载指令的复用由内存传播逻辑负责。函数调用单独分析：只有不能读取外部内存、不能修改外部状态且不进行 I/O 的函数，才允许在参数相同时复用支配当前调用的已有结果。

循环外提从支配关系识别回边，汇总同一循环头的自然循环。如果存在唯一的外部前驱，且此前驱只有一个后继，就把它作为前置块。候选指令的所有定义必须位于循环外并支配前置块。满足条件的无副作用计算移到前置块的跳转之前。

循环可能执行零次，提前计算也必须安全。因此普通算术、比较和类型转换可以外提，除法和取模只有在除数为非零常量时才外提。内存读取仅考虑不逃逸局部标量和直接全局标量，并检查循环中不存在相应写入；涉及可能修改全局状态的调用时不外提全局读取。数组和一般指针读取保留原位置。

纯函数也可能不终止，不能因为没有外部副作用就无条件外提。例如零次循环中的无限递归调用，不能在循环入口执行。本实现为循环不变调用建立“已计算”标记和结果槽，每次进入该循环前重置标记，第一次真正到达调用位置时计算，以后复用结果。参数定义必须支配前置块。每个函数最多缓存十二处调用，避免代码膨胀。

## 四、活跃分析和寄存器分配

`LiveAnalysis` 把局部标量存储位置视为可以多次定义的变量，把 IR 表达式结果视为单次定义的值。store 定义局部标量，load 使用局部标量。基本块的数据流方程为

```text
OUT[B] = 并集 IN[S]，其中 S 是 B 的后继
IN[B]  = USE[B] ∪ (OUT[B] − DEF[B])
```

从块出口逆序扫描指令时，如果对局部标量的写入在以后所有路径上都不会被读取，就删除这次存储。随后从返回、跳转、存储和调用等必要指令出发，追溯操作数定义，保留完整依赖链。

寄存器分配也复用活跃分析。每次定义与当时仍然活跃的其他值之间连边，形成干涉图。参数在入口具有隐式定义，入口同时活跃的参数两两连边。着色按跨调用需求、引用次数和稳定的名称顺序进行，减少生成结果的偶然变化。

使用的寄存器安排如下。

| 用途 | 寄存器 |
|---|---|
| 单条指令展开时的工作寄存器 | `$t0` 至 `$t2` |
| 超出 16 位范围的地址偏移 | `$t3` |
| 无需跨调用保留的值 | 优先使用 `$t4` 至 `$t9` |
| 跨调用仍然活跃的值 | `$s0` 至 `$s7` |
| 前四个函数参数 | `$a0` 至 `$a3` |
| 函数返回值 | `$v0` |

无法着色的值继续使用栈槽。函数进入时保存实际用到的 s 寄存器，返回时恢复。调用者为参数保留栈空间，第五个及以后的参数放在约定位置。栈帧按八字节对齐，并保存返回地址。内置 I/O 也按调用处理，因为运行库会使用临时寄存器。

这套处理使递归调用能够保存外层仍需使用的局部值。测试中特别覆盖了多参数递归、调用后继续使用旧值，以及超过 16 位偏移范围的大栈帧。

首轮平台反馈中，许多测试的 OTHER 指令数远高于访存数。检查发现，已有寄存器分配仍把操作数搬到 `$t0/$t1`，计算后又搬回分配的寄存器。本轮让算术、比较、加载、地址计算和条件分支直接使用分配结果，只在常量展开、溢出值和窄整数符号扩展时使用工作寄存器。窄整数扩展使用临时副本，避免改坏仍然活跃的原值。比较结果已为 0 或 1，不再重复掩码；末尾基本块返回时直接进入恢复栈帧的代码。

## 五、常量运算与跳转生成

常量乘法针对 0、1、负数和二的幂处理。二的幂转换为移位，负数乘数额外取负，其他情况使用乘法。

对于有符号的二次幂除法，直接算术右移会让负数向负无穷取整。实现先根据符号添加偏置，再右移，得到语言所需的向零截断结果。例如 `-9 / 8` 应得到 `-1`，实现不能直接得到 `-2`。

一般常量除法参考 Acc 的乘数界限算法，编译时用 BigInteger 求乘数和移位量。目标代码取得有符号乘法的高 32 位，进行移位和符号修正。负除数最后修正商的符号。中间计算使用足够宽的整数，以覆盖接近 32 位边界的除数。

常量余数使用 `x - (x / d) * d` 计算。整个展开使用保留的工作寄存器，原始被除数保存在独立位置。除数为零时保留常规指令生成路径。

加减常量只有在立即数能装入有符号 16 位范围时才使用 addiu。跳转到紧接着的基本块时直接顺序执行。条件分支仍采用局部短分支加直接跳转的方式，以支持函数体很大的程序。保留必要的延迟槽，并在开启延迟槽的模拟器中验证。

## 六、整数位宽与修改标记

常量折叠必须保留 i1、i8 和 i32 的区别。窄整数结果按位宽截断，有符号除法和比较先恢复符号。增加了带类型的 `IrConstantInt` 构造方法，打印时使用实际类型。

`midend/llvm/constant/IrConstantInt.java` 中新增的导入、构造方法和打印调整均位于成对的“代码优化新增 开始／结束”分隔注释内。本轮为克隆和拆分 IR 增加的 `midend/llvm/IrBuilder.java::SetCurrentFunction` 也使用同样的成对标记。frontend 没有新增修改。独立优化算法集中在 optimize 包，目标指令选择位于 backend 包。

## 七、跨函数优化及其边界

`SmallFunctionInline` 只内联单基本块、至多二十四条指令、不含调用和数组分配的小函数。每个调用者每轮有三百条克隆预算。克隆过程中建立参数、局部值到新值的映射，替换返回值后移除调用。原有 load/store 顺序保持不变，因此读写全局量的小包装函数也可以内联，后续传播仍按内存语义处理。

`FunctionEffects` 从局部约束开始，迭代排除调用不纯函数的候选。候选函数不能有指针参数、数组访问、I/O 或外部内存访问，只允许自己的不逃逸标量槽。这样递归函数可以保留在纯函数集合中，但间接读写全局量的函数会沿调用关系被排除。

`ConstantCallEvaluation` 在全部实参已知时解释执行纯函数 IR，覆盖分支、循环、标量槽和递归调用。结果按 IR 整数位宽处理。每轮模块求值共用二十五万条指令预算，递归深度上限为九十六，结果缓存上限为八千一百九十二项。遇到预算耗尽、未知值、除零或活动中的同参数递归时保留原调用，避免优化器自身挂起。常量递归测试 `fib(18)` 因而可以直接生成结果。

`GlobalConstants` 仅把所有写入都保持初始化值的全局标量视为常量，遇到地址外传就放弃。加减表达式还会进行有界的同类项消除，例如把 `n + m - n - m` 化为零。这让公开程序中的 `specialization_salt` 和小包装函数暴露出更多常量，继而让调用求值和循环调用缓存生效。

运行时输入无法在编译时求值。针对一个基本块内有两次以上自递归调用、含一至两个 i32 参数并返回 i32 的纯函数，后端 `RecursiveMemoization` 使用二百五十六项固定缓存。每项保存有效位、完整实参和返回值。散列只定位条目，命中必须逐个核对实参；碰撞会覆盖旧项并重新计算。原实参保存在约定的参数栈槽中，命中路径在建立栈帧前返回，未命中路径遵循原寄存器保存约定。缓存不应用于读写全局量或进行 I/O 的递归函数。

这些改动沿用原工程的 load/store IR，没有实现完整的带 phi 的 Mem2Reg，也没有声称实现完整 GCM。Salyut-J 的部分优化依赖其 SSA 和循环分析结构，直接移植会破坏本工程的数据结构；本次选择能在现有表示上验证正确性的子集。
